# 4.3 作品讲解及答疑

## 摘要

这是「新生启航计划」的最后一节直播课，吕书航老师先对两批作业做了逐份讲评：一批是以「大学启航」为主题的个人主页，另一批是以校庆为主题的静态页面。他先交代评分细则（页面完整度、页面布局、信息密度、色彩与视觉风格），再用高分作品和典型问题作品对照，说明什么样的页面算完成度高，以及 AI 辅助开发最容易在哪些地方翻车。随后课程转向进阶内容：GitHub 上的 Superpowers 工作流、Harness Engineering 怎么落地，以及「Demo 离真实上线还有多远」这个现实问题。最后是自由答疑，覆盖本地部署、模型与参数选择、网站上线、AI 味、生成内容前后不一致等具体疑问。

### 核心要点

- **提交格式**：作业必须是单个 .html 文件；交图片、录屏的作品本次未纳入讲评，实际分析了 47 份作业。
- **评分细则**：页面完整度、页面布局、信息密度、色彩与视觉风格四项，缺少要求的页面模块会相应丢分。
- **信息密度**：个人主页是简历，不是等着别人填写的表单模板；姓名、邮箱不算敏感信息，密码、身份证号、API Key 才是。
- **高分共性**：32、45、44 号（陆明飞）都做到导航与跳转逻辑正常、内容模块齐全、视觉风格统一。
- **可以加分的拓展**：任务列表勾选、亮暗双色系一键切换、用 localStorage 做数据持久化（33 号）。
- **典型缺陷**：没有跳转逻辑、写死本机绝对路径导致换环境报错、导航栏过窄或浮窗遮挡、入场动画长达 10～20 秒反而挡住内容。
- **创意与内容的关系**：3D 建模、点咖啡杯飘字这类创意应当成为内容的入口和记忆点，不能取代内容本身。
- **校庆主题**：7 号（95 分）用银杏飘落、校史滚动、校友祝福留言板营造氛围；2 号错在写了本机绝对路径；1 号是评分乌龙，只上传了 HTML 框架，实际应在 90 分以上。
- **Superpowers 工作流**：GitHub 20 多万星，流程为头脑风暴 → git 隔离工作区 → 写任务计划 → 子 agent 驱动开发 → 测试驱动开发 → 代码 review。
- **子 agent 的价值**：把大任务的记忆负担分散到多个子 agent，缓解上下文窗口满了之后的幻觉与遗忘。
- **Harness Engineering**：任务效果差时先别怪模型或提示词，可能是「驾驭框架」没搭好；可参考 GitHub 上的 Neural Harness Engineering。
- **Demo 不是产品**：真实上线还要考虑安全（越权、撞库、API 滥用）、并发、权限与数据隔离、发布更新、监控、成本。
- **成本意识**：token 涨价后，同样的任务在不同 harness 下成本与效果差距很大；他昨天跑一个很简单的任务花了 300 多万 token、4 块钱。
- **本地地址不等于上线**：127.0.0.1:8000 只有本机能访问，要给别人看必须部署到公开服务器（Vercel、阿里云、腾讯云、华为云、浪云等）。
- **名词焦虑**：prompt engineering → context engineering → harness engineering → loop engineering → graph engineering，大约每 6 周冒出一个新词，不必追。

### 课后任务

- 提交作业统一用 .html 文件；页面有跳转的，把所有网页和 CSS、JS 文件一起打包上传，路径写成相对路径。
- 到飞书文档查看自己作品的评分、问题分析和源码修改建议，再结合这些结论与 AI 进一步追问，让它做下一步优化。
- 想让自己做的网站被别人访问，需要购买服务器并部署，而不是发 127.0.0.1 的本地地址。
- 对 Superpowers 工作流、Harness Engineering 感兴趣的，可以到 GitHub 看仓库和官方文档。
- 吕老师会把作业讲评文档、源码分析、Neural Harness Engineering 相关资料分享到飞书；水墨千秋同学的免费模型 API Key 由吕老师私下提供。

## 讲稿

### 开场：这次作业怎么交、怎么评

**吕书航**：各位同学好，感谢还有 145 位同学来到最后的答疑课。这节课备课时间比较紧，PPT 做得也比较简陋，讲评过程中如果有什么问题，大家及时给我指出来，也请多多包容。

**吕书航**：先说明一个情况。作业一开始要求提交静态的 .html 文件，但有一部分同学提交了照片、录屏或者其他格式的文件。第一个标准就是必须提交 .html 文件，方便我统计分析；图片和视频这次暂时没有纳入作品讲评。

**吕书航**：本次讲评分两部分：第一部分是「大学启航」主题的作业，第二部分是之前提到的以校庆为主题的静态页面。

**吕书航**：后续如果大家感兴趣，我可以介绍一下我是怎么搭了一个简单的循环工作流、和 AI 一起完成作业点评的。一开始的 agents.md，如果大家听过前面的课，它的地位就是系统提示词——只有这一部分是我写的。我定义了作业讲评的评分细则是什么、从哪些部分评、每部分占多少分、评分原则是什么、希望输出什么内容，都写在一个文件里，通过系统提示词的方式提供给它。

### 评分细则：四个维度

**吕书航**：评分细则有四项。第一是页面完整度：作业要求包含首页、我的经历、四年路线、开学后四周的规划、学习求助、写作说明这几个部分，缺失相应部分就会丢掉相应分数。第二是页面布局。第三是信息密度：看到这个页面，能感觉到信息是充实的，但又不至于密集到影响视觉体验。第四是色彩与视觉风格。

**吕书航**：最后分析到的作业总共 47 份，分数段大致是这样，能看到大家分数普遍偏高。大家表现比较弱的是信息密度。我留意到大部分作业的情况是：「大学启航」写的是类似于你个人信息的一份简历，虽然我们提到过不要暴露比较隐私的个人信息，但我认为像名字、邮箱，不属于很隐私的范围——不是密码、身份证号、API Key。有部分同学做成了模板式的、需要你去填写的页面，整个是一个模板页面，而不是一个简历页面，信息密度的问题主要出在这里。

### AI 挑出的三个「最佳视觉」案例

**吕书航**：除了总体打分，我还挑了几个——当然不是我挑的，是 AI 挑的，按它的审美选了三个最佳视觉案例。AI 的筛选标准是布局、配色，以及整个视觉风格的统一性和亮点。

**吕书航**：第一份，AI 觉得它视觉风格比较统一、页面完整度也比较高，不同的色彩搭配也比较好，但这份作业不算高分作业，只是看页面视觉效果而已。第二份风格比较统一和突出，整体是暗色调的科幻风、科技风，它其实也不是高分作业。最后一份是很典型的 AI 产出的前端页面风格：蓝色或者紫色调、圆角、浮窗、玻璃块一样的页面，AI 也把它挑出来了。仁者见仁，智者见智。

### 高分作品：32、45、44 号

**吕书航**：综合刚才四个评分细则——完整度、布局、密度、视觉——有三份得分最高，都在 95 分左右。

**吕书航**：先看 32 号。它的亮点是有一个入场动画，比较吸引人；其次它包含了我们要求的所有页面内容，导航逻辑非常正常，点击跳转也非常顺畅；还做了一些适当的功能拓展，它的 UI 我认为都做得非常好。

**吕书航**：第二个是 45 号，大家可以看看是不是自己的作业。它的页面风格也比较好，跳转逻辑非常正常，还做了任务列表，可以勾选。

**吕书航**：第三份高分作业是 44 号，陆明飞同学，页面风格、色彩风格、视觉体验都比较突出。这里我有一个建议：现在很多公开的网站都做了两种色系，暗色系和亮色系，你可以做相应的颜色搭配，新增一个一键切换成亮色系的功能。它的页面导航跳转逻辑也是正常的。

### 典型问题：AI 辅助开发最容易暴露的缺陷

**吕书航**：接下来是这节课的重点：分析大家在 AI 辅助开发过程中暴露了哪些缺点。我挑了几份比较典型的问题作品。

**吕书航**：第一份是模板化的信息，其实这不是重点，主要是它没有做页面跳转逻辑。整个页面的视觉体验，以及能不能比较直观地看到你的信息，相对来说都差一点。飞书文档我也会分享给大家，里面写了比较详细的分析：这个页面有什么问题、问题原因出在哪里、对应代码是哪几行、推荐怎么修改。如果这份作业是你的，你可以结合这里的问题原因和问题分析，像之前提到的，跟 AI 做进一步追问，让它对你的页面做下一步优化。

**吕书航**：第二个是 37 号，我给每份作业编了号。它的问题：目标内容折叠、浮窗可能遮挡标题；不同组件之间没有联动；导航栏没有统一坐在左侧或者页面上方，而是全部坐在上边，页面上是一个浮窗，随页面滑动一直跟随。这也是从用户易用性——怎么看方便——这个角度说的。文档里有相应的问题分析和修改建议。

**吕书航**：下一个，这个页面的布局很独特，总体是左右栏布局。第一个问题是信息密度确实小了一点，没有写很多内容，路线和规划都比较简略。优化本身比较简单，但主要问题在别处：每次点进来，它都要花比较长的时间把整个动画跑完，差不多 10 到 20 秒，甚至更久。我每次进你的页面想看完整信息，就得在这儿看着它一个字一个字跳出来，用户体验不太好。它把这个动效从增强体验变成了访问内容的前置条件——这句 AI 总结得比我好。想优化的话，可以跟 AI 交互一下，考虑优化方向是什么。

**吕书航**：这个作品的页面风格、色彩风格也比较突出，但布局我自己看了有点太挤，导航栏比较窄。而且点击之后，底部的导航栏变到了页面最底部，不是浮窗的效果。这份作业的主要问题就在这里。

**吕书航**：下一个也是模板问题，UI 也可以优化，页面太素了。这里主要讲的典型问题是占位符：你交的是一个模板文件，AI 专门把它挑出来了。

### 四个有创意的作品

**吕书航**：这个作品其实非常有创意，它搭了一个 3D 建模的模型，通过点击咖啡杯飘出来这些文字，idea 非常好。但问题是：第一，信息密度太小；第二，我们要求展示的内容、模块也不完整。后续创作当然可以通过 3D 建模这类方式让页面更有新意、视觉更有冲击感，但不应该忽略网页的本质是展示你自己的个人信息。创意交互应该成为内容的入口和记忆点，可以通过 3D 建模给大家留下更深的记忆点，但它不应该成为内容的唯一载体。

**吕书航**：第二个是 20 号，准备得有点仓促，文件没给大家拉过来。它让我印象比较深刻的是有气泡效果，整个 UI 比较有新意，不是那种千篇一律的 AI 生成页面风格。它肯定有自己的巧思在里边，肯定通过一些提示词限制，或者与 AI 多步多轮对话，才生成这样的页面。

**吕书航**：下一个是 28 号，创新点也是从页面风格这个角度说的。它整体有点类似卡通风格，卡片和色彩设计我觉得很有新意。

**吕书航**：还有就是 33 号。这个页面做到了大部分同学都没有做的事情。它的整体布局比较直观、简洁，要求的内容都有包含：学习求助、规划、四年路线，以及个人信息的展示。它做的是把数据通过 localStorage 的方式存储在本地、存储在浏览器当中，对数据做了持久化。我之前测试它持久化功能的时候填了一些内容，再次打开、刷新都不会消失。

**吕书航**：我们知道一个产品，不管是一个网页还是 App，肯定不只是一个简单的前端静态 .html 文件，它有很多部分组成。传统软件开发过程分前端开发和后端开发，前端跟后端需要数据对接、接口联调。一般来说，产品要上线，数据持久化功能都需要后端来做，存储在数据库当中。因为你的产品比较小，在前端做数据持久化也是可以的。这位同学就对数据做了持久化，使得每次打开页面、打开静态 .html 文件，或者每次刷新，之前写的数据不会丢失，解决了纯前端开发时「一刷新整个流程就归零、填写的内容消失」的痛点。

**吕书航**：数据持久化当然也有问题，比如换个浏览器打开，数据还是会消失。

### 分数背后的对比

**吕书航**：这里做了一些对比。比如 32 号，能看到它的页面风格，相较于下面这一部分模板，它对自己有比较详细的个人信息介绍。38 号就是我们一开始提到的、AI 认为视觉效果很突出的作品，但它的页面跳转逻辑和信息密度都有点问题。对比的是 45 号，它是个高分作品，是一份很完整的个人静态简历，每一部分都做得很完善，而不是单单视觉效果突出、内容也比较丰富。30 号就是我们一直提到的那个没有导航的模板文件；37 号则做了简单的导航。

**吕书航**：23 号在进入页面的时候有一个滚动的动画，引入了动画，但牺牲掉了体验：我每次进界面想把信息看完，要等很久。这两个作品想做一些页面风格的创新，可能丢失掉了页面原本的基础功能——我是为了展示自己。

**吕书航**：39 号就是浮窗遮挡、边栏比较窄的问题。我也对相应的源码做了分析，如果你的作品在里面、想继续完善优化，可以到文档里看能从哪些方向优化、该从什么角度、该怎么与 AI 交互。28 号那种卡通风格的整个页面视觉和色彩搭配是我最喜欢的，33 号则是做了持久化功能。

### 校庆主题作品讲评

**吕书航**：第一部分「大学启航」的全部内容就讲评到这里。其次，有一部分同学还针对校庆做了投稿。这个地方我也用相同的方式，与 AI 约定了整体的评分细则：既然是校庆主题，最关键的就是主题表达；其他是纯前端页面的部分——整个页面的完成度、页面布局、视觉风格，还提到校庆氛围、交互与浏览体验。作为投稿作品，对源码（不管是 HTML 还是写页面样式的 CSS）的实现质量也有一定的标准要求。

**吕书航**：大部分同学得分也比较高。这里有一个乌龙，我待会讲一下为什么它评分这么低。评分最高的是 7 号，拿了 95 分。大家一起看一下它的页面设计：作为校庆作品，首页就能感受到主题，「一路银杏金黄」，后面飘的我认为也是银杏叶，虽然不太像，但氛围营造出来了；下面有校史的滚动动画，比较巧的是我自己的人网站也有类似的前端实现；它所有的内容规划都围绕校庆主题来设计，还设计了校友祝福，我可以在这里填下对学校建校 70 周年的祝福。这是得分最高的作品，文档里有一些源码分析和为什么得分这么高的解析，当然都是 AI 产出的，感兴趣可以下来看。这个作品也有一些不足，不管是视觉风格还是源码实现，都有值得优化的地方，原作者可以仔细看一下。

**吕书航**：这个是 2 号作品，是比较典型的错误。它的整个首页 UI 我认为也实现得非常好，背后有粒子效果，也有发展历程的介绍、学科介绍，我们学校一些比较有成果的内容。主要问题是什么？上面导航栏有很多页面设计，我点击另一个页面——这是 2 号，在浏览器当中打开，一跳转它就报错。注意看它的文件路径发生了什么变化：当前是从我的电脑点进来的，换一个页面，它就变成了原作者本机的绝对路径。

**吕书航**：文件存储的位置，路径只有两种：相对路径和绝对路径。绝对路径类似于把这个位置写死了，文件层级一换，可能就找不到文件；相对路径是从同一个基准点出发去找文件。这也是我自己的理解，说得也不是很清楚，大家下来了解一下，属于基本功。因为它页面跳转逻辑写的是绝对路径，所以它去找 C 盘用户下对应的文件，但我本机是没有的，就找不到。这是第一个比较典型的问题：把本机绝对路径写进去，换一个环境打开就找不到，页面就会出现跳转错误。这里有相应的分析。

**吕书航**：第二个，我认为它的页面风格也做得非常好，但不知道同学是提交错地方了还是什么：我们原本主题是校庆，它感觉做成了电子科技大学的介绍网页，没有围绕校庆主题，得分也就低了一点。

**吕书航**：第三点就是我们刚提到的乌龙。1 号作品得了 62 分。原因是这样的：一开始我没注意文件。大家写前端时，如果页面复杂了，不可能所有前端代码都放在一个 HTML 文件里边。这位同学就把整个页面的整体框架代码只放到了 .html 文件，把页面样式、色彩搭配拆分出来了——正常开发前端就是这么写的，它新拆分出来了两个 .js、一个 .css 文件。我在本地打开页面是显示正常的，校徽有图案，页面也能渲染。但我在让 AI 评这个页面的时候没注意这个细节，只把 HTML 文件丢给了它。只有一个 HTML 文件、没有相应的样式文件时，页面就只有整体的内容框架，背景、组件、设计的 UI 都没有渲染，干巴巴的一块。AI 就认为「怎么只上传了一个文件，其他的 CSS 文件没有上传」，所以得分比较低。这是个乌龙，正常来说这个作品肯定有 90 分以上。

**吕书航**：因为提交的同学比较少，其中符合要求提交 .html 文件的——其实一开始我们没有要求格式，只是方便我自己分析——有些提交图片或者视频的同学，我这边就没有一起看。

### 一套可复用的 AI 辅助开发工作流：Superpowers

**吕书航**：下一部分。毕竟是最后一节直播课，我想给大家介绍一个东西。我们在和 AI 交互、让 AI 辅助完成任务和开发代码的过程中，这门课里提到过一个意识：你应该去形成自己的一套工作流。市面上有这么多大模型，国内国外有这么多 coding agent，最近比较火的 DeepSeek Harness，或者 Codex、Claude Code，有这么多产品，不是哪个用户量最多、在测试集上分数最高就越好，你应该找到一个自己用起来比较习惯的产品。其次，你跟 AI 交互，也要去形成一套比较符合自己的工作流。

**吕书航**：这里我选取了 GitHub 上的一个项目，有多少星我搞忘了——大家能看到它有 20 多万星，非常夸张的数字。它的工作流是服务于代码开发的，大家主要是借鉴它的思想：我怎么把一个任务场景转化成工作流。不知道大家有没有印象，好像我们在课程里给大家展示过一个 brainstorming 的 skill.md 文档，就是拿的 Superpowers 的。

**吕书航**：它的整体工作流是这样：第一步，你给它发一个代码开发任务，它就会调用 brainstorming 这个 skill，跟你做头脑风暴，向你确认一些比较关键的实现问题，然后给你提供方案，你来选择。这基本上解决了任务场景或者代码开发场景里「我的想法不是很清楚、我自己不是专业的」这个问题。头脑风暴这一部分，能先让你自己、也让模型对产品建立起一个比较直观、比较系统的视图，大致看到最终形成的产品是怎样的。

**吕书航**：之后它会做工作区的隔离，用 git。可能有部分、甚至大部分同学不知道这是什么——它是一个用于版本管理的工具。代码开发过程当中肯定有 A 版本、B 版本、C 版本：现在代码是 A 版本，做了一些优化或者新功能开发，编成了 B 版本，怎么安全、科学地把整个代码从 A 版本切到 B 版本？或者说多人协作的场合，很多人一起开发项目，代码怎么管理？就需要用到 git 这样的版本管理工具。它第二步就相当于新建了一个工作区，创建一个完全隔离的、不会污染你原有代码的环境。

**吕书航**：第三步，其实我们之前也讲到，先计划、先写任务计划书，它会调用一个 writing plans 的 skill，把计划先写下来。下一步就开始开发。这里提到一个 Sub-agent Driven Development，它其实不是一个 agent 从头跑完所有任务，而是：你在写计划的时候会把一个大的任务或者复杂的工作流程拆分成很多步，第一步做什么、第二步做什么，它把这些细化的步骤分发给不同的子 agent。这有点类似于我们提到的「专家团」：主进程跑的、你跟他交互的 agent 类似团长，下面这些子 agent 就是团长分发任务的对象。

**吕书航**：它解决了一个什么问题？我们之前讲过，模型有上下文窗口，一个比较复杂的任务有很多步骤，当上下文窗口满了之后，会出现幻觉、遗忘，工作效率下降。通过子 agent 驱动的开发方式，它把一个比较大的记忆负担分散到了多个子 agent 上。

**吕书航**：第五点是 Superpowers 我认为最有特色的地方：它的开发哲学是测试驱动开发（TDD）。这里我就不展开了，涉及到比较专业的内容，是需要真正完成代码开发的同学才会接触的。如果你是计算机专业或者软件工程专业，感兴趣的话，它的代码仓库名字就叫 Superpowers，在 GitHub 上搜得到，可以自己去实践、实操一下，看它是怎么用测试驱动开发的哲学来提高 agent 的任务完成率的。最后它还会做代码的 review，做一些收尾工作。

**吕书航**：我想说的是：这套开发流程当然设计得非常科学、合理、完备，是经过无数开发者验证的一套工作流，但它不一定适合你，不一定适合所有人。其他人在探索和开发的过程中，有其他的任务场景，也可以自己去设计这么一套工作流，把它编写成 skill，再通过一些方式把这些 skill 串联起来，形成属于你自己的 workflow，就像 Superpowers 一样。这就是我想讲的第一个东西：AI 辅助开发的工作流分享，GitHub 上叫 Superpowers。当然 GitHub 上还有很多其他的工作流开源项目，我自己在用的只有 Superpowers，感兴趣可以下来了解。

### Harness Engineering：把「驾驭框架」搭好

**吕书航**：下一个想讲的是 Harness Engineering。我们课程当中对 harness engineering 只做了简单的概念介绍，停留在理论上，讲了它是什么，但具体怎么落地？这也是我最近在学的东西。harness engineering 可能对真正需要进行代码开发的同学价值更高一些，这里我不做详细阐述，文档我已经写完了。但我希望大家认识到一个点：包括我自己实践下来，Harness 确实是一个非常重要的东西。

**吕书航**：如果你想让模型按照你的预期去完成你布置的任务，第一步可能想的是怎么设计我的提示词。如果是简单任务，一轮交互、一个会话窗口就结束了。如果是复杂任务——比如有些同学正儿八经想自己实现一个网页、想做一个 App——怎么让 AI 辅助开发？

**吕书航**：首先是降本增效。现在 token 确实挺贵的，DeepSeek 涨价太多了。像我昨天跑了一个非常简单的任务，花了 300 多万 token，花了 4 块钱，搁过去可能只要几角钱。在 token 比较贵的情况下，你怎么去降本？同时怎么提高效率？花同样的时间，跟 AI 交互时用不同的 harness 框架，可能会产生效果差距非常之大的两种结果。

**吕书航**：我学习参考的资料也是一个 GitHub 的开源项目，有兴趣可以记一下，叫 Neural Harness Engineering，它对怎么去搭建一个属于自己的 harness 框架做了比较系统的阐述，也有官方的学习文档。它提到一个观念：当你的任务效果比较差的时候，不应该先去考虑模型的问题——现在模型能力很强了，工作效果差不一定是模型的问题，也不一定是你提示词的问题，有可能就是你本身的 harness 没搭好。

**吕书航**：如果你有代码开发需求，有比较复杂的目标，比如自己想做一个个人网站，我觉得也是比较复杂的开发任务——不管你是科班还是非科班，只要你有兴趣、有这个目标，我觉得 harness engineering 也是你应该学习的东西。感兴趣的话我可以把文档分享给大家。

### Demo 与真实上线之间有多远

**吕书航**：第三点。现在很多同学做的作业，或者自己动手让 AI 辅助开发的功能，比如有了一个 idea，在 AI 辅助下、在很短的时间内就产出了一个实现基本功能的 demo。demo 的意思是演示的样品，它不是一个完整的产品，它只是用于演示，或者验证我的 idea 可不可行。

**吕书航**：为什么想说这一点？我看到有部分同学在写了自己的页面、做了这么一个 demo 之后，就在想我的软件产品、我的网站能不能上线、能不能部署到服务器上，开放给大家访问、让所有人一起使用。这里存在一个问题。如果你真的是零基础——可能一开始体验到 AI 辅助开发的威力，认识到模型能力有多强之后，就觉得好像代码开发是件很简单的事情——我针对的是这类真有这种想法的同学，想讲一下一个产品的 demo 距离真实上线还有多远。

**吕书航**：这里没列全，只是简单列了 10 个从产品 demo 到真实上线存在的、真实的软件工程问题。

1. 你的产品是不是安全的？网站也好、App 也好，会不会遭受一些网络攻击，安全怎么设计？比如你的产品想开放给大家，就有登录的功能或者其他功能，你该怎么守护用户的信息隐私？数据保存在数据库里边，你该怎么防止数据库不被攻击？真实上线时，可能会发生越权、撞库、API 滥用等等这些安全问题。
2. 你现在自己拿着一个 demo 用着确实很顺畅，但真实上线之后 100 人用、1000 人用，你的产品会面临什么问题？很快你的服务就被打垮了，打垮了怎么修？接下来又应该做怎样的防护措施，来应对流量高峰？
3. 权限与数据隔离。比如你不想哪天别人用他的账号密码登录，登的却是你的账号，你自己做这么一个有登录系统的东西，这些问题都需要考虑。
4. 怎么发布更新，怎么监控软件产品真实上线之后的运行情况？
5. 服务部署到服务器上，成本该怎么控制？

**吕书航**：还有很多问题都需要考虑。所以说一个产品 demo 到真实上线，中间需要考虑的问题是非常多的。

**吕书航**：一句话而言：现在模型极大降低了把想法做出来的门槛。我们有一个 idea，在很短的时间内不需要任何配合，我自己和 AI 就可以把想法变为现实。我自己也有这种感受，我 idea 很多，想做很多东西，可能应对我生活里一些特定的场景，只服务我自己一个人，不需要开放、不需要上线，这种 idea 我就可以很快把它做出来，节省我的时间精力。我认为 AI 极大降低了这类任务的门槛。

**吕书航**：但是，它没有消除真实世界软件工程的复杂度。不管你是做软件开发，还是其他行业，不管你是信通的、电子的还是其他专业的。AI 能取代的是已经存在方法论、已经有行之有效的固定一套方法的这些东西；它不能做真正需要创新、真正存在于人脑知识里的那些知识。

**吕书航**：所以我想通过这一点给大家警示一下：可能大家现在觉得 AI 能力好强，能帮我做这个做那个，但你要区分你的任务场景。你不可能说什么都让 AI 去用，通过简单的自然语言交互，AI 就能帮我把所有事情做得服服帖帖、什么问题都没有，这是不可能的。虽然 AI 现在能力这么强，我们需要学习的东西还有非常多。

**吕书航**：这里也比较搞笑：AI 迭代速度很快，一些方法、一些名词，在 agent 开发这一行有一个比较典型的现象——可能每 6 个周就出一个新名词。从一开始的提示词工程（prompt engineering），到上下文工程（context engineering），到现在的 harness engineering，已经有了很多新的名词；还有 loop engineering，怎么把一些重复做的事情固化成一个可循环的工作流，很多个工作流组合起来，就完全可以替代我本人的工作；还有什么 graph engineering，图工程。agent 开发这一行可能每 6 个周就会诞生一个全新的名词，大家看到也不用焦虑。网上也有一句话：很多东西你不用现在去学，等你学会的时候，这个词已经过时了。

**吕书航**：大家当然可以去了解 harness engineering 是什么，也可以思考我学这个东西有没有真实落地的需求场景、有没有必要学。

### 三个高频的实操问题

**吕书航**：接下来是一些典型问题。

**吕书航**：第一，有些同学在保存网站的时候，保存成了本地网站。具体体现是什么？不知道大家刷抖音有没有刷到一些笑话：一些外行、零基础的同学在学习的时候，兴冲冲地把自己用 AI 搞的、觉得很厉害的东西想发给别人看，结果发过去的 URL 就是 http://127.0.0.1 这样的网址。127.0.0.1 指的是你的本机；8000 端口指的是你的应用部署在本机的哪个端口上。这个 URL 只是你本机、你自己在电脑上能访问。在同一个局域网、同一个网段下，其他设备带上你本机的真实 IP 或许能访问，但大部分看这个页面的人不可能跟你在同一个局域网下，所以你把网址发给别人，他肯定看不到。你需要把它部署到公开的服务器上。我记得真有人在群里把静态页面免费部署在了 Vercel 或者其他这类提供免费部署服务的网站上，只不过会限制访问次数。一定是要部署在公开的服务器上的。

**吕书航**：如果你想把网站真正部署到服务器上，服务器怎么搞？你可以找模型服务器厂商，比如阿里云；我自己用的是浪云，大家有需求可以找我当推荐人。你买一个服务器，它就会给你一个 IP，你就能把自己的应用部署在远程的服务器上，通过服务器的 IP 做公开的访问。

**吕书航**：第二，跳转文件不全，就是刚才提到的：你的网页可能不止一个，存在跳转逻辑，就应该把所有网页都打包上传，目标路径不能写成绝对路径，要写成相对路径。包括刚才那个反面例子——其实不是同学的，是我的例子——他把一个网页拆分成了三个部分：一个 .html 文件写整个页面的框架和内容，其他是样式文件，CSS 也好、JS 也好，这三个部分应该一起打包上传。当然那位同学做得很好，他是一起上传了的，只不过一开始我没有注意到。

**吕书航**：第三，上传网页的事。这次有很多同学的作业交上来是图片、录屏，很多没有分析到，主要存在的问题就是你交的不是 .html 文件。.html 和 png、jpg、mp4 一样，都只是一个文件格式；png 格式的文件怎么上传，.html 文件就怎么上传。你只需要找到文件保存在哪个位置：一开始提供的问卷里有一个「添加文件」，如果是电脑提交，就到文件系统里找到你的 .html 文件在哪个路径，上传就可以了，逻辑是一模一样的。

### 我这套评分工作流是怎么搭的

**吕书航**：有同学问那个东西是怎么打分的，我介绍一下。整个流程其实比较简单，因为备课时间比较短、有点紧张。

**吕书航**：我实现的就一个 agents.md，类似系统提示词，告诉它任务背景、评分细则这些信息。然后写了一个 Python 脚本，就是一个 review 的循环——也不是我写的，其实我把任务需求跟它说清楚，它就能产出这么一个循环脚本。单次可以跑，一次可以跑四份作业，当然也可以设置。就这样搭了一个非常简单的工作流来完成这个事情。

**吕书航**：校庆的也好、「大学启航」的也好，这里是有 48 份。所有作业，我的工作时间加起来可能就半个小时左右。每一份作品都有一份单独的 review result 产出：每份作业的评分是怎样的、哪里做得好、哪里应该优化、建议是什么，都输出一个对应的 markdown 文件，还有一个总括的、把全班汇总的输出。我只是把这个内容弄到了飞书文档上，比较适合展示。大家下来有需要的话，可以把 .html 文件发给我，我给你打个分。

**吕书航**：我最开始的提示词是什么？我叫它给我生成一个 agents.md 的文档，交代任务背景，给它一个基础的评分角度：页面完整度、页面布局、信息密度、色彩风格；后面这三点我也让它跟我进行一个头脑风暴，一起想好怎么打分——因为时间比较着急，我没有时间细想。就一个很简单的初始提示词，它就产出了一个非常完整且详细的评分细则。最后我再让它按目标格式产出：之前也提到，你想让 AI 产出什么东西，应该告诉它。我就告诉它给我产出一个 50 行的 agents.md 文档，它就直接写出来了，复制粘贴丢过来，仅此而已。

### 自由答疑

**吕书航**：接下来是最后一个部分，自由问答。会议里的各位同学还有什么问题想问的，方便解答的我直接在这里讲；也可以下来私聊我，我就在大家的群里，我就是吕老师，没有取什么外号。

**问：自己的网站想让别人访问，一定要买服务器吗？**

**吕书航**：肯定需要购买服务器。服务器本质上是一台远程服务器，你可以理解成你自己的电脑本质上也可以作为一台服务器用，但其他人想接到你的电脑上，可能会有很复杂的路由逻辑或者权限管控；而且你的电脑上有很多个人信息，你也不能把自己的公网 IP 暴露在公网上，肯定有风险。你买的这些服务器——腾讯云也好、阿里云也好、华为云也好，或者我自己用的浪云——其实就是服务器厂商自己有很多服务器，不管部署在国内还是海外。你买了服务器，就拿到了使用权，就可以把自己的应用部署上去。刚才说的 127.0.0.1 是你本机的 IP，本地的网页、应用部署在你自己的电脑上，所以要用这个 IP 去访问；把服务部署在远程服务器上，你就可以拿远程服务器的 IP 去访问你部署在上面的应用。不同服务器厂商、云服务厂商有什么优劣，可以下来比较一下。

**问：「添加 agent 可以接入的软件」是什么意思？**

**吕书航**：我没有太听明白，你说的是 MCP 吗？可以再说得详细一点。（学员补充后）我理解了。我们之前在第四节课最后那几个问题里提到过这个点：未来互联网的生态，很多新开发的软件产品有一个基本的趋势——从只面向用户开发，转向不仅面向用户开发，也需要面向 AI 开发。

**吕书航**：这里顺便说一个东西。比如飞书，我现在所有的操作都基于飞书 App 这么一个可视化页面，直接点击、操作这些资源。但是我们知道，大模型或者 AI 不能像我们人一样看到可视化页面然后去做点击，它做不到。那它怎么做？它需要通过命令行（command）的方式。飞书做的事情就是把它所有软件产品的应用接口、所有的 API 改写成命令行的形式——在 PowerShell 或者 bash 里输入的那些命令。通过命令行方式暴露所有软件产品的接口，再把这些命令和相关的说明书丢给 AI，AI 就知道怎么来用你的软件了，也就相当于把你的软件产品接入到了 agent 里边。

**问：Codex 本地部署需要多高的配置？**

**吕书航**：Codex 是 coding agent，是 agent 的产品，它不是一个模型，不存在本地部署的说法。它就是一个普通的 App，你想在本地运行的话非常简单，几千块钱的轻薄本，三四千块的轻薄本肯定都可以跑这个软件，没有什么配置的负担要求。你接的 API Key，模型不是运行在你的本地，而是运行在 GPT 公司那边，它可能有这么庞大的服务器集群，模型运行在服务器集群上。Codex 它只是一个 coding agent，是一个软件产品，不是模型，不需要部署，你只是安装；当然可能需要一些「魔法」才能用。

**问：用 AI 做这些工作，是不是需要先学一点代码？**

**吕书航**：我认为你当然可以去了解一些代码的工作。有一个概念叫「干中学」。代码开发是一个非常庞大的领域——我的老本行是做 Java 开发的，光 Java 开发这件事情，你就需要学非常多的技术栈，总的来说也是一个比较复杂的东西。但是现在有了 AI 之后，你只需要针对你要做的任务场景，在做的过程当中去学。我认为你现在最先需要学的就是怎么与 AI 交互，包括这节课提到的提示词工程、harness engineering。知道怎么与 AI 交互之后，你想学有关的代码知识，本质我认为比较高效的方法也是与 AI 交互：通过一些提问，或者让 AI 给你制定一些学习计划，你完全可以基于 AI 来学一个特定的代码知识。这就叫干中学，你可以在做事情当中边去学习。

**吕书航**：肯定是需要有一些基础的。说实话，你想做一个自己的个人网页，如果你想真正做到自己设计这个网页、让模型按照你的预期来输出，我认为也算是一个比较复杂的事情，它不是简单的事情——当然现在有很多成熟的做个人博客的产品，你可以下来了解。你的态度是态度，方法是结合 AI 来做学习。看不懂代码是正常的。

**吕书航**：如果你的产品只是属于一个比较初期的阶段，那还好；如果后续你有很多想拓展的功能边界，想把个人网站发展成一个很大的、集成的东西很复杂的东西，你就需要去系统地学习一些东西。你不能说看不懂代码，那后续的框架搭建、其他功能开发，或者现有功能的优化，肯定都是需要看得懂代码的，肯定是需要有代码基础的。

**问：游戏本可以本地部署模型吗？**

**吕书航**：我没有做过这个事情。我自己也是游戏本，我认为可能 8B 顶天了，4B、8B 顶天。8B 模型跑在游戏本本地的话，对整个电脑 GPU 的负担是很大的。一般如果你想做本地部署，可以去买一个那种独立的 Mac 小圆盒，两三万块钱，可以在本地部署一个参数量比较小的千问模型。

**问：有没有比较推荐的免费模型 API Key？**

**吕书航**：之前在群文档里我有提到，现在突然想不起来了，下来同学私聊我，水墨千秋同学你私聊我吧，我下来给你。免费的模型 API Key 肯定有限制：一是模型能力，厂商肯定不会把其他人付费能够享受到的模型免费暴露出来，模型能力比较一般；其次，你需要去排队，不能畅用。

**问：AI 做出来的东西会不会有比较明显的「AI 味」？**

**吕书航**：我觉得分任务场景。比如做 PPT，AI 做的 PPT 你一眼就能看出来是 AI 做的，AI 味比较重。但要是写文档的话，如果你用的是能力比较强的模型，它没有那种非常明显的 AI 痕迹，至少全篇的内容逻辑是通的，不存在前后相互矛盾的点。

**吕书航**：不过最近有一件比较「狗」的事情。不知道大家关没关注，就是这几天新出的：国外的 GPT、Claude、Gemini 做了一个事情——如果你通过这些模型去产出一些文件，不管是 Word 也好、其他格式也好，它其实会在文件里埋一个 AI 的身份标识，如果有人来检测一下，就能通过标识检测到这个文件是 AI 生成的。它都不用去看你的内容，而是在格式上、文件属性上埋了这么一个东西。我不知道国内有没有，现在你都不用考虑格式的问题了：如果你用的是国外模型生成东西，有心人去查，一定知道这是 AI 生成的，不用看内容，直接看文件属性。具体原理我不知道。

**问：AI 生成视频、写小说时，经常出现同一个东西前后不一致，怎么办？**

**吕书航**：生成视频，包括不止生成视频——你让 AI 给你写小说，你也会发现它确实存在很多前后细节对应不上、前后矛盾的问题。理论上，我们说的提示词工程也好，我教你们的 skill，或者其他的 rule、tool，本质都是提示词。方向肯定是可以通过更细节的提示词解决：比如先用一份非常详细的提示词，把你想生成的东西说清楚，把它所有可能的形状、大小、表情，或者面部的五官特征等等都说清楚，理论上是可以解决这个问题的。我觉得这也是一个比较难的问题，因为我自己没有用 AI 生成过视频，这个问题我不敢多说，我不是专业的，你可以下来继续探索，方向是用更细节的提示词解决，理论上成立。

**吕书航**：说到「去 AI 味的提示词」，我觉得也挺搞笑的。像知网、万方，还存在「用 AI 去降低 AI 率」这种服务，我觉得是非常荒谬的事情，怎么可能做得到。你不需要去考虑你写出来的东西有没有 AI 味，你应该去考虑的是怎么用提示词把问题说清楚，让你的产出有它自己的逻辑、有自己的思想在里边，其他人看不出来是 AI 写的。我判断一个东西是不是 AI 做的，可能是它存在前后矛盾，前面内容跟后面内容风马牛不相及。你不需要去考虑去 AI 味，因为现在一些头部模型厂商，不管国内国外，产出的文档至少看起来已经不像 AI 写的了，只是考究细节还会有这些问题。用「去 AI 味」的提示词让 AI 把 AI 味去掉，我觉得逻辑上行不通，是比较荒谬的一件事情。

**问：电脑自带的 AI 和网页上的 AI 有什么区别？**

**吕书航**：网页版的 AI，比如 DeepSeek，它底层调用的是 DeepSeek 的 chat 模型；而你用 API Key，我现在就可以调 DeepSeek 最前沿、最新的旗舰模型，比如 V4 Pro、V4 Flash，最近 DeepSeek 还出了一个多模态，不再是纯文字。API Key 可以调更多的模型，网页版只能调那种能力可能有点阉割的 chat 模型。电脑自带的 AI 有模型广场，可以在广场页调整模型输出的一些参数，比如第一节课提到的 temperature、top K 等等，你可以调一些参数，感受不同参数下 AI 输出的效果有什么不同；网页版的 AI 是调不了这个东西的，比如 DeepSeek 的聊天页，它是一套默认的设置。

**问：修改一个 UI 设计，但修改前后 AI 给的东西基本一模一样，怎么办？**

**吕书航**：首先，可能你当前的模型能力不太好、比较一般。其次，我觉得还有一个可能的原因，就是你的上下文现在已经很满了、爆了，AI 就存在幻觉问题。如果你一直在一个会话窗口跟 AI 交互，聊天内容一长，它确实没办法比较准确地接收你给的指令，任务完成的效果也不好。你可以考虑：第一，找一个更好的模型；第二，新开一个会话，然后再接着试一下。

**吕书航**：这里我也推荐两个我自己在用的、调整前端 UI 的 skill。一个叫 UI UX Pro Max Skill，专门优化项目的 UI 和 UX，它也有 12 万多星，得到了 GitHub 社区比较广泛的认可，就是用于 UI/UX 优化的。Skill 是什么？就是其他人已经写好的、用来调整 UI/UX 比较好用的提示词，你直接拿来用而已，它不是什么高端的东西，它也是提示词。所以可以从三个方向优化：一是换更强的模型，二是新开一个会话，三是借用别人写得比较好的提示词。
