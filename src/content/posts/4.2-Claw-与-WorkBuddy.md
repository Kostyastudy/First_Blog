# 4.2 Claw 与 WorkBuddy

## 摘要

这是「AI 入门」系列的最后一讲，主题是把前几节课学到的选模型、写提示词、沉淀 Skill 的能力，装进真正会规划、会调用工具、会交付文件的 Agent 系统。课程先梳理 Agent 的技术脉络：从只内置四个基础工具的 Pi，到靠消息渠道实现跨设备常驻的 OpenClaw，再到腾讯把它产品化的 WorkBuddy 桌面工作台，并解释这条路径上每一步都在降低使用门槛。第二部分拆解 WorkBuddy 的默认权限与安全沙箱、模型与 API Key 配置、助理（消息渠道）、自动化、专家与专家团、Skill 与 MCP 等核心组件。第三部分用「英语学习助手」做课堂实战，演示如何让 Agent 先扮产品经理澄清需求，再换全栈负责人视角出 MVP 方案、UI 规范与实施计划，并对比 WorkBuddy（DeepSeek V4 Flash）与 GPT 生成结果的差异。最后，讲师谈了三个问题：人会不会被 AI 取代、未来软件生态如何面向 Agent 重构、大学生使用 AI 的边界在哪里。

### 核心要点

- **Pi 的定位**：最小的 Agent Harness，只内置 Read、Bash 等 4 个基础工具，把复杂能力交给 Package（本质上就是 Skill）；工具越克制，定制越灵活。
- **横向对比**：Codex 内置约 19 个以上核心工具，像全能工具箱；Claude Code 内置 12 个，围绕编码协作做得很完整。
- **OpenClaw 的创新**：基于 Pi 的最小底座，加上网关、会话、消息渠道、常用 Skill，实现跨设备持续工作，这是它出圈最关键的原因。
- **OpenClaw 的四个痛点**：部署复杂、安全与权限风险、token 成本高、稳定性与维护成本高。
- **WorkBuddy 的定位**：腾讯推出的全场景职场 AI 智能体桌面工作台，开箱即用，兼容 OpenClaw 的 Skill 生态，覆盖日常办公与代码开发两类场景。
- **默认权限与安全沙箱**：所有操作在沙箱内进行，高风险操作（改文件、删文件）要用户确认；本机环境不建议开「完全访问」，服务器或虚拟环境可以开。
- **模型配置**：内置混元、智谱、MiniMax、Kimi、DeepSeek 等国内模型，也可用 API Key 接自定义模型，费用走自己的账号，DeepSeek 的 Key 只能复制一次。
- **助理就是消息渠道**：可配微信助理、微信客服号、企微助理、QQ、元宝，以及飞书、钉钉；人在外面用手机发消息就能派活。
- **自动化**：把「每周末推口语小测」「每隔几小时推飞书待办」这类周期性任务做成模板，可设提示词、执行频率、生效区间与推送渠道。
- **专家与专家团**：专家 = Skill + 特定方向的经验；专家团 = 多 Agent 协作，由主理人（交付总监）拆解任务并分派。
- **Skill 的三种用法**：查找技能（自动生成提示词并安装）、上传技能（文件夹或压缩包，必须含 skill.md，带 YAML 格式的 name 与 description）、创建技能（调用 skill creator）。
- **MCP 是协议**：MCP 解决「Agent 怎么连外部系统」，回答「我能用什么」；Skill 是工作流，回答「这件事怎么做」；两者广义上都属于 Tool。
- **一句话总结**：Agent = 大模型 + Harness。大模型负责思考，Harness 把思考变成可执行、可验证的行动。
- **实战方法论**：产品经理视角澄清需求 → 全栈负责人视角出 MVP 方案与流程图 → 定 UI Style Guide → 出可独立验证的实施计划 → 按计划实施。
- **AI 时代的三个判断**：创造力不可替代；未来软件要面向 Agent 暴露接口；大学里把 AI 用在低价值任务上省时间，高价值任务只让它提供范式。

### 课后任务

- 结合第三节课准备的四个 md 文件，产出英语学习助手的 Agent Web 应用（@全体学员）。

## 讲稿

### 开场：给大模型接上手和脚

**沐子学长**：各位同学，欢迎来到本次 AI 入门系列课程的最后一讲——Agent 与 WorkBuddy。之前的课程里，我们学习了 Prompt、Skill 以及 Harness 等基础概念，对 Agent 也有了初步的了解。我们之前提到，大模型像人类的大脑，它可以思考、推理、学习，但是没有手脚和身体，它什么都做不了。Agent 就是接上了手脚和身体的大模型，是一个完整的人。

**沐子学长**：这节课我们继续理解 Agent 的技术演进，讲解国产龙虾、也就是腾讯龙虾 WorkBuddy 的核心能力，掌握用 Agent 搭建应用、做任务规划的方法，让 Agent 真正开始为我们工作。前三节课我们学会了三件事：第一节课学会选模型、第一次与大模型协作；第二节课提示词工程，学会怎么写任务说明书；第三节课 Skill 与 Harness Engineering，学会把可复用的工作流沉淀成 Skill。今天，我们把这些能力装进真正会规划、会调用工具、会交付文件的 Agent 系统。

**沐子学长**：这节课主要分四个部分。第一，Agent 的技术脉络，从 Pi 到 OpenClaw，再到 WorkBuddy。OpenClaw 在今年三四月份大火过，短暂地出圈了一段时间。第二和第三部分，讲腾讯龙虾 WorkBuddy 的基础使用与核心能力。最后一部分，结合「英语学习助手 Agent」的课堂实战，讲我们如何与 Agent 交互，最终产出的理想状态下的网页端 Agent 是什么样子。

### 一、Agent 的技术脉络

#### Pi：最小的 Agent Harness

**沐子学长**：接下来看第一部分，也就是 Pi Agent。这是 Pi Coding Agent 的官网页面，它的标签、slogan 是「There are many agent harnesses, but this one is yours」。为什么说这个 Agent 是你的？下面有一行小字注释：Pi 是 minimal agent harness，最小的 Agent Harness 框架；「Adapt Pi to your workflows, not the other way around」，意思是把 Pi 通过搭配结合到你现有的工作流里，而不是别的什么方法。

**沐子学长**：为什么这么说？先看一个对比。Pi 把 Agent 缩小到一个清晰、可嵌入的最小底座。Codex，也就是 OpenAI 的 coding agent，内置了约 19 个，或者 19+1 个、甚至更多的核心工具，工具覆盖面很广，更像一个全能型的工具箱；Claude Code，也就是 Anthropic 的 coding agent，内置了 12 个工具，围绕编码协作，丰富度和完整度都很高。Pi 的产品逻辑是刻意保持 Agent Harness 工具的极简，只有 4 个最基础的内置工具：读取文件的 read、命令行操作的 bash、编辑改写等等。它把复杂能力交给我们自己去定制的 extension 扩展、技能以及 package。

**沐子学长**：Pi 的重点不是默认工具越多越强，而是默认工具越克制，你定制就越灵活。所以它说 Pi 是真正属于你自己的 Agent Harness，你可以结合自己特定的工作场景去定制需要什么扩展、什么技能包，它把 Agent 缩小到了一个清晰、可嵌入的最小底座当中。

#### Package 与 Skill

**沐子学长**：那么 Pi 通过什么形式扩展功能？答案是 package。Pi 的官方文档里讲了 package 的结构，其中的核心文件就是我们上节课讲到的 skill.md。所以你把 package 理解成一种 Skill，是完全可以的。

#### OpenClaw：跨设备的常驻助理

**沐子学长**：Pi 到 OpenClaw 又经历了怎样的产品演进？OpenClaw 在官网公开感谢过 Pi——它就是基于 Pi 的最小化底座搭建起来的框架。它在 Pi 的基础上添加了网关、会话、消息渠道、工具以及一些常用的 Skill，让 Agent 能够跨设备地持续工作。跨设备的持续工作，是 OpenClaw 最核心的创新亮点，也是它出圈、如此火爆的最关键原因。

**沐子学长**：答案就在消息渠道。这里给大家一个抖音视频的链接，视频里的 up 主结合自己的工作和生活场景，让 OpenClaw 真正成了一个可用的「赛博秘书」。我摘了几段文案。第一，OpenClaw 直接根据 B 超结果出一份可行性报告，同时调出历史化验记录，为博主的病因做分析，并根据常驻地搜索最权威的医院。

**沐子学长**：拆开看它做了几件事：一是分析 B 超结果、生成报告；二是调用之前发给它的历史化验记录，为当前的病做病因分析；三是根据常驻地搜索最权威的医院、我该去哪个医院就诊。它把看病、分析报告、选医院这整条生活化的流程都串起来了。

**沐子学长**：它还能让家人明白我的病是什么——根据文字报告输出一个可视化网页，也就是我们之前实现过的静态 .html 简历页面那样的东西，再推送到服务器上变成公开报告，其他人通过具体的网址就能公开访问。它也可以根据已有的保险信息，评估这份重疾险到底值不值得买、保险公司有没有在 80 页废话文学的 PDF 里埋坑。

**沐子学长**：工作场景里，它可以集成博主常用的飞书，7×24 小时采集用户的聊天记录、会议记录，并持久地保存到记忆系统中。记忆系统就是我们上节课提到的 harness 当中的记忆层，它能让 Agent 记住哪些信息重要、哪些信息可以丢弃。基于这些信息，它可以周期性地帮用户梳理飞书消息待办，比如每隔几个小时就推一份飞书消息待办给用户。

**沐子学长**：它还可以结合硬件，把手机 App 的通知都转发给 OpenClaw。这个功能非常强大：比如每天定时推送几个重要微信群里有什么重点话题和交叉洞察，我就不用每次都去水群、爬楼；再比如结合我当前在跟谁聊什么话题，从中取材，定时推送相关的英语口语练习题——学英语也好，学日语也好，都能通过这种方式推送。博主还结合多邻国 App 设计了一个错题沉淀系统，每周末推送 15 道小测验。除此之外，它还能帮忙改稿、写评语、算绩效、恢复颈椎、加练身体等等。

**沐子学长**：有一点很打动我：他给孩子设置了一个专门的记忆机制，用来存储孩子的成长里程碑。等孩子 20 岁、30 岁以后再回过头看这份由 Agent 替他存储的记忆，我觉得是非常好的画面。所以 OpenClaw 如果用好了，它能实现的功能、它的潜力是非常巨大的。

#### 从 OpenClaw 到 WorkBuddy：四个痛点

**沐子学长**：那么 OpenClaw 到 WorkBuddy 又有一个什么样的跃迁？这是从开源探索走向产品化落地的一个典型对比。OpenClaw 有四个常见痛点。第一是部署复杂，这也是它出圈热度来得快去得也快的核心原因，甚至出现了一些帮忙部署龙虾的活动和市场。第二是安全与权限风险。第三是成本，它的记忆系统上下文比较丰富、比较复杂，token 消耗量也比较大。第四是稳定性与维护成本。

**沐子学长**：那么如何把能力稳定地交付给用户？腾讯的回答就是 WorkBuddy。它的产品化特点首先是降低部署门槛：你可以直接到官网下载安装，按用户指引一步一步完成，更适合普通用户，不需要任何专业流程的部署，也更容易落地。

**沐子学长**：后面我们会讲到，WorkBuddy 针对不同的应用场景设计了不同的 Agent Harness 特点，它也兼容 OpenClaw 的开源 Skill 生态，保留了生态的可复用能力，让已有的 Skill 可以延续价值。OpenClaw 展示了 Agent 的能力边界，WorkBuddy 作为一个产品，更强调稳定交付、易用性与落地体验。

**沐子学长**：腾讯官方对 WorkBuddy 的定位是：腾讯推出的全场景职场 AI 智能体桌面工作台。官方产品文档里介绍了两个适用场景。一是日常办公，面向职场的通用工作场景，可以帮你完成文档生成、数据分析、PPT 生成、深度研究、邮件编辑、周报生成、批量文件处理等常见办公需求。二是代码开发，它提供了面向代码开发场景的模式，可以辅助我们完成日常的编码开发。

### 二、上手 WorkBuddy：安装与首页

**沐子学长**：接下来到 WorkBuddy 的官网，看它是如何下载的。在官网能比较直观地看到两个下载入口，浏览器搜索 WorkBuddy 就能找到。点击下载后跳转到下载页，我是 Mac 就下 Mac 版本，是 Windows 就下 Windows 版本，点击后它就在后台开始下载。因为我已经下载过了，就不再重复下载。

**沐子学长**：安装也是非常傻瓜式的，一直点下一步，选一个相应的安装位置，WorkBuddy 就安装成功了。

**沐子学长**：WorkBuddy 的首页长什么样？大家可以简单看一下，有几个点需要注意。首先它主要分成左右两块布局：左侧是工具栏与项目空间，右侧是与 Agent 的对话窗口以及一些快捷选项，总体非常简洁直观。

**沐子学长**：首页要重点介绍两个点。第一个是「默认权限」。你可能会想，默认权限是什么东西？点击它可以看到：当前为默认权限，所有操作都会在安全沙箱约束内进行，超出范围的会请求你的允许。安全沙箱指的是 WorkBuddy 的工作环境在一个类似有安全限制的箱子内。比如它想修改甚至删除你的文件，这类高风险操作就会请求你的允许。如果我点击「完全访问」，开启之后 AI 会减少确认步骤，可以执行更多的操作，包括一些敏感操作、文件修改和外部执行操作。诚然它是有风险的，但好处是减少我们人工的确认步骤。

**沐子学长**：我比较建议的做法是：如果你的工作环境、你的工作空间在本机，不管 Mac 还是 Windows，我都不太建议开启完全访问。因为这种情况下 Agent 拥有了读写你硬盘上所有文件的能力，万一哪个疏忽，它不小心误删了核心、关键的文件，你整个电脑都用不了。如果你的工作环境是服务器、是一个虚拟环境，开启完全访问后能大大减少人工确认带来的时间成本，Agent 真正具有了独立完成长线工作任务的能力，而不用你一直坐在电脑前。否则，Agent 哪怕读一个文件都要问你可不可以读、改一个文件都要问可不可以改，你就得一直坐在电脑前点确定。完全访问有风险，但也带来了一定的便利性。

**沐子学长**：其次，右下角有一个「自动」标签。自动指的是什么？你可以在这里选取 Agent 底层调用的模型。WorkBuddy 内置支持许多国内比较先进的模型，比如自家的混元、智谱、MiniMax、Kimi，还有 DeepSeek，这些国内厂商它都支持。

### 三、核心能力：模型、助理、自动化、专家、Skill、MCP

#### 配置自定义模型与 API Key

**沐子学长**：但我要讲的是如何配置一个自定义模型，这里涉及一个新的概念：API Key。我们以 DeepSeek 的官方开放平台为例，浏览器搜索「DeepSeek 开放平台」就能到达页面。点击右侧创建一个新的 API Key，把它填入 WorkBuddy 相应的位置，就可以通过 API Key 的方式调用你自己的 DeepSeek，扣的当然也是你自己账号的钱。需要注意的是，DeepSeek 官方的 API Key 只能复制一次，如果你选 DeepSeek 作为主力模型，就要注意保存好它。设置好之后，你可以直接在 WorkBuddy 里与 DeepSeek 交流，而不是每次都到 DeepSeek 官方网页去访问它的网页 AI。

#### 助理：把消息渠道接进来

**沐子学长**：接下来介绍「助理」。点击助理页面上的小齿轮，可以进行助理设置。助理就像我们刚才讲到的 OpenClaw 的消息渠道。因为 WorkBuddy 背靠腾讯，与腾讯的生态结合得非常紧密，你可以在这里配置微信助理、微信客服号、企微助理、QQ、元宝，以及腾讯之外的飞书、钉钉等等，和 OpenClaw 是殊途同归的东西。配置好之后，你可以通过手机微信给 WorkBuddy 发一条消息，或者通过 QQ 发一条消息，非常方便。你可以想象：出门在外，电脑不在身边，你通过 QQ 或微信直接把活派给 WorkBuddy，想让它做什么就用消息的形式发过去，这个体验非常不错。

#### 自动化：周期性任务模板

**沐子学长**：第二个要介绍的是自动化功能。刚才讲 OpenClaw 时提到，那位博主设置了一些周期性的任务，比如每周末推送口语练习的小测验、每隔一定时间推送一次飞书任务待办，其实都是所谓的自动化。WorkBuddy 为了提升易用性，作为一个面向普通人的产品，做了很多自动化任务模板，可以直接选取，并配置相关的提示词、执行频率、生效区间，以及需不需要推送到指定的消息渠道，都可以设置。这是 WorkBuddy 做得比较方便的一个自动化功能。

#### 专家与专家团

**沐子学长**：下一个要介绍的是 WorkBuddy 引入的一个新概念：专家、专家团。专家卡片能展示对应专家的能力介绍、擅长领域和任务示例，告诉我们这个专家是干什么的、擅长领域是什么、我们怎么调用。专家团展示的信息差不多，只是多了一个团队成员的介绍。专家团就像……我们前面一直在讲的是人工与单个 Agent 的协作，而专家团是人工与多个 Agent、一个 Agent 团队协作，团长在这里叫「交付总监」，也就是主理人，它自动把一个大任务拆解成多个小的任务步骤，分配给特定方向相关的 Agent 执行，并返回一个完整的结果。如果我们点击「召唤软件开发团队」，它会直接跳转到首页与 Agent 聊天的页面，可以看到它调用的软件开发团队，你在这里填写需求就行。

#### Skill：查找、上传、创建

**沐子学长**：下一个是我们比较熟悉的 Skill。相关概念我们已经介绍很多了，WorkBuddy 也内置了许多常用的、由其他用户分享的 Skill。这里我主要介绍如何查找、上传、创建 Skill。点击「查找技能」，它会直接跳转到一个页面，自动生成一句提示词——「帮我查找并自动安装某某功能的 Skill」，它给你提供一个提示词模板，你只需填写这个 Skill 需要完成什么功能，WorkBuddy 就能自动完成查找和安装的整个流程。

**沐子学长**：如果我想上传一个已有的 Skill 文档，可以点击「上传技能」。它对文件的要求是：可以是一个文件夹或一个压缩包，但必须包含 skill.md 这个核心文件；skill.md 需要包含 YAML 格式的技能名称和描述，也就是上节课讲到的 Skill 元数据——name 名字是什么、description 以及相关的触发词是什么，只是要通过一种特殊的 YAML 格式来编写。YAML 格式是什么？你只要按照之前课程给的 Skill 模板编写，它就符合要求；想深入了解可以自己查一下，我这里不做过多的展开。

**沐子学长**：那如何创建一个技能？点击「创建技能」，它也会跳转到这个页面，自动给你调用一个叫 skill creator 的 Skill——它本质也是一个 Skill，通过调用一个 Skill 来帮你创建一个实现特定功能的 Skill。

#### 专家、专家团、Skill 怎么选

**沐子学长**：这三者有什么区别？这是从 WorkBuddy 官方文档里摘下来的图。Skill 你可以理解成一个可复用的能力；专家就是在 Skill 的基础上多了特定方向的专家经验，比如多了一些知识，或者接了外部的知识库等等；专家团则是多个专家一起形成的多 Agent 协作流程。

**沐子学长**：怎么选？你想让 AI 具备某种工具能力，可以直接去装特定的 Skill。如果你有一个明确的单点问题，可以直接去找一个专家，让他给你生成一个方案，或者提供建议，专家也可以直接帮你干活，因为它本质上等于 Skill 加特定方向的经验。如果任务复杂，你觉得专家搞不定，需要多个角色配合，就可以召唤专家团。

#### MCP 与连接器

**沐子学长**：好，我们介绍下一个东西：什么是 MCP？MCP 我们已经介绍过，WorkBuddy 的 MCP 在这里叫「连接器」，我不做过多的介绍。我们只要知道 MCP 是 Agent 的一种标准化的外设接口。也正是得益于之前讲解到的 MCP 协议，WorkBuddy 才能够内置如此多的 MCP 工具，因为它是基于同一套范式来开发的。

#### 一条持续降低门槛的路径

**沐子学长**：从 Pi 到 OpenClaw 再到 WorkBuddy，主要的产品路径是每一步都在降低使用门槛：Pi 作为开发者可嵌入的底座，OpenClaw 做常驻助理，WorkBuddy 作为开箱即用的办公工作台。如果作为零基础的普通人使用，我当然推荐 WorkBuddy；如果你是想学习 Agent 的有关架构、想自己搭建一个 Agent，我非常建议大家去了解一下什么是 Pi、什么是 OpenClaw。Pi 就是一个最小的 Agent Harness，它回答的是模型如何调用工具，你去看它的源码，就可以知道模型是如何调用工具的逻辑；OpenClaw 更像一个完整的助理系统。因为它的部署门槛比较高，大家更多选择了 WorkBuddy 这个桌面办公工作台，它开箱即用，普通人拿上来就可以直接使用，并不需要学习任何的前置知识。

#### Skill 与 MCP 的辨析

**沐子学长**：这里我们来辨析一下 Skill 与 MCP。前面提到，我们对 Skill 的定义是 AI 智能体可以按需取用的可复用技能包；而 MCP 是一种调用协议。可以简单看一下两者的区别：MCP 本质上是一种协议，它主要解决的是 Agent 怎么去连接外部系统，关注的问题是「我能用什么」——比如我要访问数据、要查看某个文件、要搜索什么，它更像一个 USB 接口，是一个可插拔的功能。而 Skill 阐述的是一套工作流，是一个可复用的任务技能包，它回答的问题是「这件事情怎么做」，它更像某个操作手册，更像一个菜谱。

**沐子学长**：这里需要引入一个新概念：Tool。广义来讲，Tool 的定义是 Agent 可以调用的一切能力。MCP 和 Skill 本质上都是在给 Agent 增加能力，因此都可以被看成是 Agent 的 Tool 模块。但严格来讲，MCP 是一种协议——全称 Model Context Protocol——不是一个能力模块。逻辑是：我们通过 MCP 协议去调用 MCP 服务商提供的 Tool。比如我和小明约定好，我可以借用小明的橡皮擦：MCP 作为协议，就是我和小明的约定；MCP 服务商在这里就是小明；橡皮擦就是我们可以使用的 Tool。

**沐子学长**：我们之前讲到，MCP 是 Agent 标准化的外部接口，怎么理解「标准化」？就像秦始皇统一六国之后推行车同轨、书同文、统一度量衡。在 MCP 出现之前，各家厂商开发的模型能够调用的外部接口各有各的标准、各有各的要求，需要分别去适配；就像六国统一之初，每个地方有不同的纸币，货币流通非常困难。而 Claude 像秦始皇一样推出了 MCP 的统一规范标准，告诉大家以后开发第三方接口都按照 MCP 的标准来。所以简单理解，MCP 也就是 Agent Tool 这个 Tool 的一部分。

**沐子学长**：狭义来说，Tool 就是一个模型可以选择调用、具有明确输入输出契约的可执行能力。从这个角度看，它的工作流程是：模型选择一个工具，工具需要传入什么参数，工具执行完把执行结果返回回来，这就是一个 Tool 的工作流程。

**沐子学长**：广义的话，你可以把 MCP 和 Skill 都纳入 Tool 的范围。我这么理解，这样理解也比较容易接受。

#### 再定义 Agent

**沐子学长**：那么我们来给 Agent 下一个新的定义。我们之前一直说 Agent 像一个数字实习生，是大模型接上了手和身体，能够工作、能够具体去执行某些操作。这里给它下一个更准确的定义：Agent 等于大模型加 Harness。Harness 是一个外壳，是大模型的手脚、身体，它让模型得到了去调用工具、去执行真实任务的能力。

**沐子学长**：在 Agent 当中，大模型只负责思考——负责想、负责推理，它理解用户目标，完成推理、规划、生成决策，判断什么时候该调用什么能力；而 Harness 提供给大模型这些需要调用的能力。上节课我们提到编排层、执行层、记忆层以及反馈层，分别负责不同的职责。而 Tool，广义来讲是 Agent 可以调用的一切能力，包括 Skill、MCP 以及一些狭义的 Tool 具体工具，Agent 通过 MCP 协议完成外部能力的标准化接入。一句话总结：大模型负责思考，而 Harness 负责把思考变成可执行、可验证的行动。

### 四、课堂实战：英语学习助手 Agent

#### 第一步：让 Agent 扮产品经理澄清需求

**沐子学长**：接下来来到这节课的实战：如何从零与 WorkBuddy 完成交互，实现一个英语学习助手 Agent。先看我给 WorkBuddy 的第一份提示词。我先调用了网站设计这个 WorkBuddy 内置的功能，并告诉它先不要写代码。我只有一个比较模糊的产品想法：我想实现一个 Agent Web 应用，它的定位是单词背诵助手 Agent，只设计单词背诵的功能。

**沐子学长**：上节课我们自己也设计了英语单词 Agent 有什么功能、这个功能有什么可复用的流程，我在这里设计了四个流程：第一，上传词书，解决上传词书的能力；第二，把单词生成我可以背诵的单词卡片；第三，复习；第四，生成测验题。我把这四个流程都告诉它。

**沐子学长**：然后我给它设定了一个身份：像一个产品经理，先帮我澄清，也就是所谓的头脑风暴的技巧。对每个问题告诉我：我需要决定什么、这个问题为什么重要、在没有特别偏好时你推论的默认方向是什么，不要询问无关的细节，现在不要设计页面，也不要生成代码。这份提示词，如果你看过我在第二节课发给大家的飞书文档，就会发现它是直接复用了文档当中某一节的提示词，只是针对特定的任务场景做了轻微的改写。

**沐子学长**：这里就能看到 WorkBuddy 开始提问，Q1、Q2、Q3、Q4、Q5、Q6、Q7、Q8。为了省时间，我直接告诉它「所有基于你的默认推荐为准」，它每一个环节都有一个默认推荐的方案。于是它产出了一个产品方案。

#### 第二步：换全栈技术负责人视角出设计方案

**沐子学长**：接着我让它换一个视角，从产品经理切到全栈技术负责人，来设计这个产品：它已经有了产品方案，我让你再生成一个设计方案，这个方案需要包含哪些内容、你推荐什么开发顺序。这里它产出了一个 MVP 最小化的产品方案，还生成了相关的流程图，让我们比较直观地看到当前的页面逻辑是怎样的。

#### 第三步：定 UI Style Guide

**沐子学长**：下面就是给 Agent 定 UI 的基调：界面的色彩、风格或者页面布局。我从这节课之前推荐的网站里选取了认为还可以的 UI 参考发给它，让它重点分析哪些内容，整理成我们的 UI Style Guide v1，依旧告诉它不要实现具体的业务页面。然后它就开始提炼页面的色彩风格、视觉风格，形成了 UI 的设计规范。

#### 第四步：出实施计划并执行

**沐子学长**：接下来我继续让它生成一个完整的执行计划：我们之前有了产品文档、有了设计文档，执行每一步骤应该做什么？这些提示词同样是复用的，在飞书文档里都提供给了大家。我告诉它产品方案是什么、设计规范是什么，让它把这一整个复杂的页面开发任务拆成一步一步、每个步骤可以独立验证、独立完成的计划书。它交付了一个实施计划；后面我让它严格按照实施计划开始实施，最终生成了一个 MVP 的最小化实现版本。

#### 系统提示词与「专家」功能

**沐子学长**：这里有一个题外话：如何设置系统提示词？飞书文档里提到，合理地设置系统提示词是提示词工程当中一个比较实用的技巧。我看了一下，WorkBuddy 其实没有官方的、针对某个特定任务设置提示词的入口。我想的办法是结合它的专家功能：点击专家，新建一个专家，它调用的其实是一个叫 expert manager 的新建专家 Skill——「帮我创建一个什么专家，擅长什么，我的经验是……」，你把自己对专家的预期、希望专家有什么功能告诉它，它就会帮你生成。我生成了「全栈开发协作者」，刚刚的页面里你也能看到，后面的开发工作我都实打实地调用了这个全栈开发协作者。

**沐子学长**：系统提示词的本质，是在每一轮对话、每一轮任务中都把我给它的提示词带上。专家也是一样：你把它的身份设定为专家之后，它对于专家的一些说明书也会一并带上，交给 AI 去处理。所以从本质上讲，这个专家的说明书也就是一种系统提示词。

#### 两个 Agent 的产出对比

**沐子学长**：接下来看一下 WorkBuddy 产出的结果。我用相同的提示词，一份给了 WorkBuddy，一份给了工作模式的 GPT，来看看同一份提示词、两个不同的 Agent 产品，产出的产品效果是怎样的。

**沐子学长**：先看 WorkBuddy 生成的首页。它提供了词书功能，也就是我们提到的 Skill——如何上传词书。这里只是它内置的一些单词，你也可以通过固定的格式把想背诵的单词粘贴进来。比如我选一个四级高频的内置词书，它本身就抽取了 18 个单词；我把单词数量稍微调小一点，选取 10 个单词。

**沐子学长**：这就是第二个 Skill：创建单词卡并生成学习卡片。第一张卡片是 admire，点击它可以翻转——这个逻辑我没有参与设计，是模型自发的行为。翻转之后有它的例句、中文释义、记忆提示。学完一张点下一张，analyze，下一张、下一张……

**沐子学长**：学完之后进入第三步复习。它的复习逻辑是计数：点击「认识」的次数达到三次，就把这个单词的状态设置为复习完毕，跳到下一个。然后是最后一个 Skill：生成总结测验题，让我们选择对应的英文单词，比如「钦佩、欣赏」对应的就是 admire。整个流程就是这样。

**沐子学长**：我快速点一下，让大家看看最后的报告。查看本轮报告，它最后生成了本轮复习的单词背诵报告，可以看到哪些是薄弱词，也可以复制薄弱词再来一轮，重走这个流程。当然，这个页面现在依旧是一个静态页面，每次点击重置、刷新，整个数据就会丢失。

**沐子学长**：再看 GPT 用相同提示词生成的页面是怎样的。加载比较慢，我们直接看这里。首先比较直观的是它的首页风格，色彩风格或者页面布局已经比 WorkBuddy 表现得稍微好一点。我不是说 WorkBuddy 的工程能力有什么问题：我在执行任务的时候，底层调用的是 DeepSeek V4 Flash 的模型，客观来说，V4 Flash 和 GPT-5.6 Luna 的模型能力差距还是有的。

**沐子学长**：GPT 相较于 DeepSeek V4，用相同提示词生成的页面好在哪里？这里我可以接入自己的 API Key，是真实的，填入相应的 API Key，我们也展示了如何去获取自己的 API Key，然后测试并连接。我这里只用演示模式，带大家看一下这个 GPT 生成的 Agent 是怎样的。

**沐子学长**：我们也能感受到 GPT 相较于 DeepSeek V4 有了什么提升。第一，它的界面更直观地体现了当前页面的定位——它是一个 Agent，需要去展示我是怎么与 Agent 进行交互的、Agent 完成了哪些步骤。最开始的首页有一个比较小的窗口，不知道大家看见没有，在这个小窗口里，它其实有介绍：在生成学习卡片和生成总结测验这两步，它是真实需要去调用相应的模型来生成卡片和测验的；而在执行背诵循环的时候，就只是本地的 Harness 在完成操作。

**沐子学长**：它生成学习卡片之后，单词卡片的布局甚至配了相应的图——现在我们没有接入模型，配图只是内置的。点击之后有示意，我选择「认识」，卡片里有相应的例句，也有相应的联想。整个页面的风格、视觉体验，作为用户我觉得是非常好的，至少比 DeepSeek V4 生成的要好一点。

**沐子学长**：然后它生成总结测验题，来看一下我们哪些是真的记住了，比如 resilient。我也快速带大家过一下，主要看最后生成的总结报告，它的页面风格也比刚才展示的要稍微好看一点。点「开始新的一轮」，又回到了这里。这就是我们预期的：通过提示词工程的办法与 WorkBuddy 或者说你常用的一些 coding agent 交互，生成帮助我们背单词的 Web Agent 是什么样子。有小的工具，它也不会花费我们多少时间。

#### 后续可优化的方向

**沐子学长**：当然，因为时间关系，这堂课的演示项目只是一个非常简单的最小化项目。后续还可以从哪些方面进行优化？

**沐子学长**：产品侧，我可以实现一个完整的词书导入功能，设计一个复杂的遗忘曲线，对每日、每周的学习进行统计分析，还可以定义自己的学习计划。数据侧，可以做一个数据持久化——刚才的页面只是一个静态的前端页面，它的数据不是保存在某一个地方的，每次刷新之后所有数据就丢失了，所以你也可以考虑一下数据持久化的功能怎么实现。

**沐子学长**：用户侧，可以做一个登录系统，登录之后可以制定一些个性化策略，并结合数据持久化：只要用户登录进来，相应的背诵数据、偏好数据就可以进行加载。Agent 侧，可以从一个单词助手升级成真正帮助我们学习英语的助手：现在只设计了背诵单词的功能，后面可不可以设计口语练习、帮助我们修改作文、帮助我们练习阅读等等，这些都是可以升级的方向。页面侧，可不可以新增一些内容，把前两节课学到的简历页面、规划页面、课表页面都融入到当前的页面里，真正做一个自己的个人网站？我觉得这个事情非常酷。

### 五、AI 浪潮下的三个思考

#### 问题一：人会不会被 AI 取代

**沐子学长**：那么这节课到这里，甚至可以说我们这次 AI 入门系列课程所有关知识点的内容，就已经讲解完了。接下来我还想给大家介绍的是，我们在当今 AI 浪潮下的一些思考。

**沐子学长**：第一个问题，我在第一节课提到过：人类究竟会不会被 AI 取代？我当时在第一节课的说法，不知道大家还记不记得——因为人类有逻辑之外的、也必须在沉默当中去传递的这部分知识和共识，从这个角度出发，人类就一定不会被 AI 取代。

**沐子学长**：这节课我想从另一个比较切实、比较实际的视角来讲。我们知道，人类去学习，真正有价值的不是重复大家都知道的东西，真正有价值的是创造。AI 是一个概率压缩模型，它学习了人类已有的很多逻辑规律，所以它很容易去重复那些基本不需要动脑的行为，或者把很多算法落地成某种特定成型的样子的行为——它是从人类的语言逻辑，或者说我们已有的这些知识里学习得出来的规律。在 AI 之前，我们用传统方法编程的时候，基本上是知道某个代码规则怎么写，或者怎么去注册一个蓝牙断开的消息处理、Python 怎么做一个 sigmoid 的算法。

**沐子学长**：这些代码开发的场景，都不需要我们自己去记住，而是遇到这个场景，我们到浏览器上搜一个参考实现，拷贝过来，落地到代码当中即可。所以其实在过去，大部分程序员或者大部分工程师做的也是这么一个重复的事情，不是创造的事情。这个落地过程基本上就是工程师大脑休息的时间，因为我们只是把别的地方摘了过来而已，我们并没有真正地去动脑。

**沐子学长**：那么现在有了 AI 之后，这些不用动脑的过程、或者说我们重复的这些流程，我们只是代理给了 AI，我们自己的核心作用一直都没有被取代。如果稍微遇到稍微复杂的程序，最终还是需要我们人来自己去创造，我们真正不会被取代的部分是我们的创造能力。

**沐子学长**：AI 不会取代人类。至少在代码编辑这个场景，它为人类工程师减去了很多重复造轮子所需要的时间和精力。其他行业也一样：你的行业，或者说你的学习，你自己的主观能动性能够支撑你去创造一些没有的东西，那么你就一定不会被 AI 取代。那为什么现在有很多人都在担心、或者在焦虑自己会被 AI 取代？因为他现在做的活本身就是 AI 会干的活，也就是很机械地去重复一些内容，它没有创造的过程。这是我们要聊的第一个问题。

#### 问题二：未来软件生态的结构性变化

**沐子学长**：第二个问题，在 AI 浪潮下，未来的互联网生态会有什么结构性变化？这个点专业性稍微有一点强。我结合已有的一个场景——全屋家居智能——给大家讲解一下。

**沐子学长**：现在的全屋家居智能，我们都知道大致的应用逻辑：它有一个语音助手，我可以跟它说一些话。它的底层逻辑是去匹配我说的话当中的一些关键字，非常机械死板地匹配我说的内容在它的语料库里面有没有，这样它就能够「理解」——所谓的理解要打引号——知道我想让它做什么，然后调用相应的指令或者工具来完成操作。如果我不巧换了一个说法，这个说法没有在它的语料库当中，它就没有办法，只能说「我不知道你说的是什么意思，我不理解」。所以说现在的全屋家居智能，它的智能助手其实不是真的智能，它只是机械地在匹配而已。

**沐子学长**：现在的全屋家居有什么方向？以小米的 App 为例：通过小米的家居管理 App，我在外边要到家的时候，可以把屋内的空调打开、电视打开，或者把扫地机打开。我是通过 App 完成这些功能的。那么我可不可以把 App 的功能接口，除了通过手机上的可视化页面形式暴露给人类之外，也通过另外一种方式暴露给 AI？这当然是一个可行的方案。

**沐子学长**：包括飞书——我一直提到的工作软件，是我用得最多的，飞书云文档写文档非常方便，我推荐大家下来体验一下。飞书最近做了什么事情？它推出了一个叫飞书 CLI 的东西，CLI 指的是命令行、命令行指令、命令行操作。有了飞书 CLI 之后，我就能够通过命令行的一些指令去调用飞书的工具。这个指令我人都可以用，AI 为什么不能用？我把相关的技术文档或者指令集发给 AI，解释这个指令可以做什么，AI 是不是就可以结合飞书的能力，通过这些指令完成我之前必须自己操作的飞书有关功能？

**沐子学长**：这是一个非常大的方向。在未来的软件发展过程中，一定会有越来越多的 App 或者小程序诞生，它除了需要去设计如何面向人类之外，也肯定要去设计如何面向 AI、如何给 AI 提供对应的功能接口，软件的主要趋势或者方向会变为面向 AI Agent 的开发。

**沐子学长**：现在还有很多企业或者公司，也在思考如何把当前 AI 的能力结合到他们已有的企业流程当中，以节省更多的人力物力，把人力、金钱成本投入到其他更多的、需要创造的场景，更多需要探索的场景，也就是人类还没有形成知识体系的场景。这也是企业结构调整或者革新的一个方向。

#### 问题三：大学里使用 AI 的边界

**沐子学长**：第三个问题：大家马上要进入大学，你在大学中使用 AI 的边界是什么？比如我上大学的时候，有一些水课需要生成一个文档、生成一个 PPT、交一个作业。对于我自己而言，你要有这么一个价值判断的过程：它对于我的发展有没有价值？我通过这件事情真的能够学到一些知识、提升我自己的能力，还是我为了拿到这节课的一个学分？你可以判断一下，如果是后者，你当然可以用 AI 来节省自己的时间和精力。

**沐子学长**：如果是一些你需要去思考、你需要去创造的任务场景，我认为 AI 最多只能够作为给你提供范式、或者提供范例的这么一个角色，它不能够真正地去代替你去做这件事情。所以使用 AI 的边界在于：你什么东西都丢给 AI，你会面临一个非常严重的后果——你可能会失去思考的能力。人是不能够停止思考的。

**沐子学长**：使用 AI 的边界，停留在逻辑的边界上。边界以内，我们能够说出来的、可以推理的、已经有的这些东西，这一部分恰恰就是 AI 擅长的；而边界以外，我们需要去思考的、需要去创造的，或者说一些同属于我们所有人类的、不可言说的、只能在沉默当中传递的那一部分，是人类所擅长的。我们不能够把我们所擅长的东西丢掉。

**沐子学长**：举个例子，在诗歌创作或者文学创作的场景，过去我考虑过让 AI 辅助我完成一些诗歌创作或者小说创作。但我们都会发现，不管模型能力多强，它写出来的东西都有一种模板味，你感觉它这个东西好像在什么地方似曾相识，它这么写一定不能够表达你的初衷。我最初想通过文学创作表达什么样的情感或者思想，它是一定不能够理解这一部分的，因为这是属于全人类共有的、不可言说的那一部分，是 AI 不能够理解的。为什么有些时候我们读到一些诗词，或者读到一些文学作品，会突然就共情了、突然就潸然泪下了？这是 AI 永远都不可能触及的部分。说得严谨一点，是当今的 AI、当前基于现有架构训练出来的 AI 不可能触及的部分。

**沐子学长**：所以大家进入大学之后，现在确实会有很多焦虑：我的行业在以后会不会被 AI 颠覆，我自己会不会被 AI 取代？我觉得真正的态度就是你去学好、做好你的本职工作，去学好你真正该学的东西，保持思考，保持创造。与其去焦虑自己以后怎么就业、AI 会把这个世界变成什么样子，与其迷茫，不如走一步看一步。因为 AI 变化太快了，我们都只是普通人，我们不是天才，没办法去做 AI 时代的引领者，那么我们就只用考虑怎么去学习使用 AI，把 AI 当成工具，学习怎么使用它就行。因为 AI 的迭代速度太快了，你只需要找到自己比较上手的 AI 工具，形成自己这么一套使用 AI 的工作流，仅此而已，走一步看一步。
